# 수학 모드 (4학년 2학기 샘플) 설계

- 날짜: 2026-10-24
- 대상: 워드 아일랜드 (`index.html`, `boss.js`, `shop.js`, `avatar.js`, `items.js`)
- 브랜치: `feature/math-mode` (마음에 안 들면 브랜치를 버리고 `main`으로 돌아간다)
- 화면 시안: `.superpowers/brainstorm/1701-1792808656/content/math-hint-v8.html` (최종 힌트 시안), `math-screens.html` (시작·문제 화면)

## 1. 왜 만드나

영어 게임에서 아이가 가장 신나는 순간은 **문제를 맞혔을 때**다. 수학에서도 똑같은 성공의 기분을 주고 싶다. 수학 모드에서는 계산을 연습하면서, 틀렸을 때 **수학 개념을 쉽고 재미있게** 깨닫게 하는 것이 핵심이다.

이번 작업은 **샘플**이다. 초등 4학년 2학기 계산 단원만 먼저 만든다. 반응이 좋으면 다른 학년과 단원으로 넓힌다.

## 2. 목표 / 비목표 / 반(反)목표

**목표**
- 시작할 때 **영어**와 **수학** 중 하나를 고른다.
- 4-2 분수와 소수의 덧셈·뺄셈을 영어처럼 "답이 적힌 몬스터 잡기"로 푼다.
- 틀리면 **힌트를 볼지 아이가 고른다.** 힌트는 블록을 끌어서 수를 쪼개고 모으는 **"만들기 작전"**이다.
- 수학 코인은 영어 코인과 따로 모은다. 아바타는 하나를 같이 키운다.

**비목표 (이번에 하지 않음)**
- 도형 단원(삼각형, 사각형, 다각형)과 꺾은선그래프
- 다른 학년
- 수학용 도감, 앵무새탐정 같은 미니게임, 복습 모드
- 수학 보스의 새 펫

**반목표 (이렇게 되면 기술적으로 돌아가도 실패)**
- 정답을 바로 보여줘서 생각하지 않고 넘어가게 하는 힌트
- 분수를 `3/5`처럼 한 줄로 쓰는 것. 분자는 위, 분모는 아래에 가로줄을 긋고 쓴다.
- 수학 문제의 정답이 틀리거나, 오답 보기가 정답과 같은 값인 것 (예: `0.30`과 `0.3`)
- 기존 영어 세이브, 코인, 진행이 깨지거나 수학 진행과 섞이는 것
- 힌트에서 블록을 여러 번 끌어야 해서 번거로운 것

## 3. 제약

- 빌드 도구가 없는 순수 HTML/JS 정적 페이지다. 기존처럼 `<script src>`로 파일을 붙인다.
- 저장은 `localStorage['wordisland_save_v1']`에 든 `S` 객체 하나다. 백업 코드는 `S` 전체를 base64로 만든 것이다.
- 기존 함수 `show(id)`, `toast`, `floatText`, `sfxGood`, `sfxBad`, `tone`, `save`와 몬스터 UI, 결과 화면, 보스전, 아바타를 최대한 그대로 쓴다.
- 테스트는 `node --test tests/`로 돌리고, `tests/load.js`의 vm 방식을 따른다.
- 휴대폰(375px 폭)에서 손가락으로 쓸 수 있어야 한다.

## 4. 흐름

### 4.1 시작 화면 (사용자 결정)
- 새 사용자는 이름을 입력하고, 기존 사용자는 "이어하기"를 누른다. 그다음 **🔤 영어 섬 / 🔢 수학 섬** 고르기 화면이 나온다. 섬 카드에는 각 섬의 코인(🪙 / 💎)과 진행 상황을 보여준다.
- **(제 판단)** 마지막으로 고른 섬을 `S.mode`에 기억한다. 지도 위쪽에 "섬 바꾸기" 버튼을 두어 언제든 다른 섬으로 갈 수 있게 한다.
- 이어하기 세션(`session`)은 섬마다 따로 둔다.

### 4.2 수학 지도
- 영어 지도와 같은 모양이다. 챕터 머리말, 스테이지 버튼, 보스 버튼이 있고, 스테이지는 순서대로 열린다.
- 코인 표시는 💎(수학 코인)다.
- **(제 판단)** 수학 지도 아래쪽에는 상점 버튼만 둔다. 도감, 복습, 앵무새 버튼은 없다.

### 4.3 스테이지 한 판
- 영어처럼 한 판은 10문제다.
- 화면 위쪽에 문제를 크게 보여준다(예: `3/5 + 4/5 = ?`, 분수는 위아래로 쓴다). 소리 듣기 버튼은 없다.
- 답이 적힌 몬스터 3~4마리 중 하나를 잡는다.
- **맞히면** 영어와 같다. 잡기 효과, 소리, 콤보, 점수, 경험치, 아바타 응원이 나오고, 코인은 💎로 쌓인다.
- **틀리면** 4.4로 간다.
- 별 기준은 영어와 같다. 첫 시도에 맞힌 비율로 정하며, 힌트를 봤거나 다시 풀어서 맞힌 문제는 첫 시도 정답으로 치지 않는다.

### 4.4 틀렸을 때: 힌트 고르기 (사용자 결정)
1. 아이가 고른 몬스터를 빨갛게 표시하고, 부엉이가 "앗, 아까웠어!"라고 말한다. 정답은 아직 보여주지 않는다.
2. 버튼 두 개를 보여준다.
   - **🦉 힌트 보고 풀기** → 4.5의 만들기 작전
   - **💪 혼자 다시 풀기** → 몬스터 위치를 섞어서 같은 문제를 다시 낸다.
3. 힌트를 마치면 원래 문제를 다시 풀고, 맞히면 다음 문제로 넘어간다.
4. **(제 판단)** 혼자 다시 풀다가 또 틀리면 같은 고르기 화면을 다시 보여준다. 두 번째로 틀렸을 때는 영어처럼 정답 몬스터가 빛나게 한다.
5. **(제 판단)** 힌트를 다 본 뒤 원래 문제를 또 틀리면 힌트를 다시 띄우지 않는다. 바로 정답 몬스터가 빛나고, 아이가 그 몬스터를 잡으면 넘어간다.
6. 이어하기 세션에는 힌트 진행 상태를 저장하지 않는다. 힌트 도중에 나갔다 오면 그 문제를 처음부터 다시 낸다.

### 4.5 힌트: "만들기 작전" (사용자 결정, 시안 v8)

덧셈의 답이 자연수 경계를 넘을 때(예: 0.35 + 0.8, 2.7 + 1.4, 3/5 + 4/5) 쓰는 힌트다. 1학년 때 배운 "10 만들기"(8 + 5 = 8 + 2 + 3)와 같은 생각이다. 작전 이름에는 만들 수를 넣는다. 예: "1 만들기 작전", "3 만들기 작전".

**블록 표현**
- 소수: 판 1장 = 1, 막대 1개 = 0.1, 작은 칸 1개 = 0.01. 막대 10개가 들어가는 **틀**이 꽉 차면 판 1장이 된다.
- 분수: 분모만큼 칸이 있는 틀(5칸이면 1/5짜리 조각 5개)을 쓴다. 대분수의 자연수 부분은 판으로 보여준다.

**단계** (2.7 + 1.4를 예로)
1. 왼쪽 작업대에 2.7을 판 2장과 틀(막대 7개 + 빈칸 3개)로 보여준다. 빈칸이 깜빡인다.
   - 부엉이: "막대가 얼마 더 있으면 틀이 꽉 차서 3이 될까?" → 보기 중에서 **0.3**을 고른다.
2. 오른쪽 작업대에 1.4를 보여준다. 그중 필요한 0.3을 **초록 점선으로 묶은 묶음 하나**로 표시한다.
   - 아이가 이 묶음을 **한 번 끌어서** 왼쪽 빈칸에 놓는다(사용자 결정: 여러 번 끌지 않는다).
   - 틀 근처로 가져가면 틀이 초록색으로 빛나고, 놓으면 "딸깍" 소리가 난다.
   - 엉뚱한 곳에 놓으면 묶음이 제자리로 돌아가고, 부엉이가 "왼쪽 빈칸 위에서 손을 떼 봐!"라고 말한다.
3. 틀 아래 값이 **1**로 바뀐다("꽉 찼다" 같은 말이 아니라 숫자로 보여준다, 사용자 결정).
   - 오른쪽 작업대에는 **남은 것만** 보여준다(사용자 결정). 여기서는 판 1장과 막대 1개다.
   - 위쪽 식은 `1.4 = 0.3 + ?`이다. 아이가 **1.1**을 고른다.
4. "2.7 + 0.3은?" → **3**. 틀이 판 1장으로 바뀌고 꽃가루가 터진다.
5. "3 + 1.1은?" → **4.1** 🎉
6. 마지막에 비밀 규칙 한 줄을 보여주고, **아이가 고른 오답이 왜 틀렸는지** 짚어준다. 예: "3.11은 막대 11개를 0.11로 쓴 거예요."

**공통 규칙**
- 위쪽 식은 단계마다 바뀐다: `2.7 + 1.4` → `1.4 = 0.3 + ?` → `2.7 + 0.3 + 1.1` → `3 + 1.1` → `4.1`. 아이가 아직 맞히지 않은 값은 식에서 `?`로 가린다.
- 단계마다 보기 3개 중 하나를 고른다. 틀리면 흔들림 효과와 함께 작은 힌트 한 줄이 더 나오고, 벌칙은 없다.
- 진행 표시(점 5개)로 지금 몇 단계인지 보여준다.
- 색은 정해 둔다: 왼쪽 수는 파랑, 오른쪽 수는 주황, 옮긴 묶음은 초록, 1(자연수) 완성은 노랑.
- 끌기는 포인터 이벤트로 만들어서 마우스와 터치 모두에서 된다.

**작은 자리에서도 같은 작전** (사용자 결정)

받아올림이나 받아내림은 자연수 경계에서만 일어나지 않는다. 소수 자리 안에서 일어날 때도 **같은 만들기 작전**을 쓴다. 블록에는 막대 10칸 틀 말고도 **작은 칸 10개가 들어가는 틀**이 있다. 이 틀이 꽉 차면 막대 1개가 된다.

- **0.35 + 0.48 → "0.5 만들기 작전"**
  1. 0.48은 작은 칸 2개(0.02)가 더 있으면 0.5가 된다.
  2. 0.35에서 0.02 묶음을 한 번 끌어온다.
  3. 작은 칸 틀이 꽉 차서 막대 1개로 바뀐다(값 표시는 `0.5`).
  4. 0.5 + 0.33 = **0.83**
- **만들 수는 받아올림이 일어나는 자리에서 정한다.** 가장 낮은 자리에서 받아올림이 생기면 그 위 자리의 다음 수(0.48 → 0.5)를 만든다. 자연수를 넘으면 다음 자연수(0.8 → 1, 2.7 → 3)를 만든다.
- **받아올림이 두 번 생기는 경우** (예: 0.67 + 0.48): 가장 낮은 자리부터 한 번만 만든다(0.48 + 0.02 = 0.5). 남은 0.65를 더할 때 생기는 받아올림은 다음 단계 보기로 맞힌다. **(제 판단)** 힌트가 길어지지 않게 끌기는 한 번만 한다.

**뺄셈: "내려가기 작전"** (같은 생각을 거꾸로 쓴다)
- **0.53 − 0.28 → "0.5까지 내려가기"**
  1. 0.53에서 먼저 0.03을 빼서 0.5로 만든다(묶음을 끌어서 빼낸다).
  2. 0.28은 0.03 + 0.25로 쪼개진다(남은 것만 보여준다).
  3. 0.5 − 0.25 = **0.25**. 이때 막대 1개가 작은 칸 10개로 쪼개지는 장면을 보여준다.
- **1.2 − 0.35:** 1.2 − 0.2 = 1, 그다음 1 − 0.15 = **0.85**. 판 1장이 막대 10개로, 막대 1개가 작은 칸 10개로 쪼개지는 장면을 보여준다.
- **3 − 1.25:** 3 − 1 = 2, 그다음 2 − 0.25 = **1.75**.
- **분수:** 1 2/5 − 4/5는 1 2/5 − 2/5 = 1, 그다음 1 − 2/5 = **3/5**. 1 − 3/8은 판 1장을 8칸으로 쪼갠 뒤 3칸을 빼낸다.

**받아올림이나 받아내림이 없는 경우** (제 판단)
- 0.3 + 0.4, 1/5 + 2/5는 "같은 블록끼리 모으기"다. 묶음을 한 번 끌어서 합친 다음 개수를 센다.
- 0.7 − 0.3은 묶음을 한 번 끌어내고 남은 것을 센다.

### 4.6 문제 만들기 (제 판단)

문제는 정해진 목록이 아니라 **규칙에 따라 그때그때 만든다.** 스테이지마다 생성 규칙을 둔다.

| 챕터 | 스테이지 | 예시 |
|---|---|---|
| 🍕 분수의 덧셈과 뺄셈 | 1. 진분수 + 진분수 (합 < 1) | 1/5 + 2/5 |
| | 2. 진분수 + 진분수 (합 ≥ 1, 대분수로 답) | 3/5 + 4/5 |
| | 3. 대분수 + 대분수 | 1 2/7 + 2 6/7 |
| | 4. 진분수 − 진분수, 1 − 진분수 | 4/6 − 1/6, 1 − 3/8 |
| | 5. 대분수 − 대분수 (받아내림) | 3 1/5 − 1 3/5 |
| | 👹 보스 | 챕터 전체 섞기 |
| 🧱 소수의 덧셈과 뺄셈 | 1. 소수 한 자리 덧셈 | 0.3 + 0.4, 2.7 + 1.4 |
| | 2. 소수 두 자리 덧셈 | 0.35 + 0.48 |
| | 3. 자릿수가 다른 덧셈 | 0.35 + 0.8 |
| | 4. 소수 뺄셈 | 0.7 − 0.3, 1.2 − 0.35 |
| | 5. 자연수 − 소수 | 3 − 1.25 |
| | 👹 보스 | 챕터 전체 섞기 |

- 분모는 2~12 사이, 같은 분모끼리만 계산한다(4-2 범위). 대분수로 답할 때는 가분수 대신 대분수로 쓴다.
- 오답 보기는 **아이들이 자주 하는 실수**로 만든다.
  - 분수: 분모끼리도 더하기(7/10), 대분수에서 자연수 빼먹기(2/5), 자연수로 바꿀 때 하나 덜 넘기기(1 1/5), 받아내림 실수. 정답이 1 2/5일 때 값이 같은 가분수 7/5는 보기에 넣지 않는다.
  - 소수: 자리 안 맞추기(0.35 + 0.8 = 0.43), 받아올림을 0.11처럼 쓰기(3.11), 소수점 위치 실수
- 보기들은 **값이 서로 다르고**, 정답과 같은 값을 다르게 쓴 보기(0.3과 0.30, 7/5와 1 2/5)는 넣지 않는다.
- 같은 판 안에서 똑같은 문제는 나오지 않는다.
- 각 문제에는 힌트 종류(4.5의 만들기, 내려가기, 모으기, 빼내기 중 하나)와 힌트에 쓸 값을 함께 계산해서 붙인다. 값은 받아올림이 일어나는 자리, 빈칸 크기, 묶음, 남은 것, 만든 수다.

## 5. 저장 데이터 (제 판단)

```js
S.mode = 'eng' | 'math'            // 마지막으로 고른 섬
S.math = {
  coins: 0,                        // 💎 수학 코인
  stages: {id: {stars, best}},     // 수학 스테이지 기록 (영어 S.stages와 분리)
  trophies: {bossId: stars},       // 수학 보스 트로피
  session: null,                   // 수학 이어하기
  skills: {kind: {c, wrong}},      // 문제 유형별 정답/오답 수 (나중에 약한 유형 연습에 쓸 수 있게)
}
```

- 경험치와 레벨, 연속 출석(`streak`)은 **두 섬이 같이 쓴다.** 아바타가 하나라서 같이 자라는 것이 자연스럽다.
- 수학 스테이지와 보스 id는 영어 id와 겹치지 않게 문자열 접두어 `m`을 붙인다(예: `'m-fr1'`, `'m-boss-fr'`).
- 세이브를 불러올 때와 백업 코드로 복구할 때 모두 `ensureMath(S)`로 빠진 필드를 채운다. 기존 데이터는 지우지 않는다.

## 6. 상점 (사용자 결정)

- 아바타는 하나다. 영어 상점에서 산 모자와 수학 상점에서 산 망토를 같이 입을 수 있다.
- 상점 위쪽에 **🔤 영어 상점 / 🔢 수학 상점** 탭을 둔다. 어느 섬에서 들어와도 두 상점을 다 볼 수 있다. 각 상점의 아이템은 그 상점의 코인으로만 산다.
- `items.js`의 아이템에 `cur:'eng'|'math'` 필드를 추가한다. 기존 25개는 모두 `'eng'`이다. `Avatar.canBuy`와 `Avatar.buy`는 아이템의 `cur`에 따라 `S.coins` 또는 `S.math.coins`를 쓴다.
- **(제 판단)** 수학 아이템은 슬롯마다 1~2개씩, 모두 8~10개를 만든다.
  - 예: 📐 삼각자 칼, 📏 자 지팡이, 🧮 주판 방패, 숫자 무늬 망토, ➕ 이펙트, 🔢 모자
  - 수학 아이템의 `word` 자리에는 한국어 이름을 쓰고, 발음은 들려주지 않는다.
- **(제 판단)** 수학 상점에서는 "영어로 주문하면 10% 할인" 대신 **"계산 문제 맞히면 10% 할인"**을 쓴다. 지금 열려 있는 수학 스테이지 범위에서 쉬운 문제 하나를 낸다.
- 첫 방문 선물과 오늘의 특가는 영어 상점에만 있다. 수학 아이템은 선물과 특가 후보에 넣지 않는다.
- **(제 판단)** 수학 트로피는 영어 쪽 잠금 조건(`{trophies:n}`), 트로피 방, 앵무새 열림에 세지 않는다. 수학 아이템의 잠금 조건은 `{level:n}`(같이 쓰는 레벨) 또는 새 조건 `{mathTrophies:n}`만 쓴다.

## 7. 보스전 (제 판단)

- 각 챕터 끝에 보스를 둔다. 하트, 분노 모드, 요정 부활, 트로피, 💎 보상 흐름은 기존 `boss.js`를 그대로 쓴다.
- 보스 기술은 화면 효과 계열인 거미줄(web), 얼음(ice), 유령(ghost), 자리 바꾸기(swap), 그림자(shadow), 시간 제한(timer)만 쓴다. 영어 전용 기술(spell, robot, sentence)은 쓰지 않는다.
- 보스전에서 틀렸을 때도 4.4 힌트 고르기를 보여준다. 단, 시간 제한 기술(timer)은 힌트를 보는 동안 멈춘다.
- **(제 판단)** 하트는 몬스터를 잘못 잡을 때마다 하나씩 잃는다. 처음 틀릴 때와 혼자 다시 풀다가 틀릴 때가 모두 해당한다. 힌트 안의 단계별 보기에서 틀리는 것은 하트를 잃지 않는다. 힌트는 벌이 아니라 도움이어야 하기 때문이다.
- 보스를 이기면 트로피와 💎를 준다. 새 펫은 주지 않는다.

## 8. 분수 표기

- 분수는 분자 위, 가로줄, 분모 아래로 쓰는 진짜 분수 모양이다(`inline-flex` 세로 배치, 가운데 `border-top`).
- 대분수는 자연수를 크게, 그 오른쪽에 작은 분수를 붙인다.
- 문제, 몬스터 보기, 힌트, 결과 화면 모두에서 같은 함수 하나로 그린다.

## 9. 소리와 말

- 정답, 오답, 콤보 효과음은 영어와 같다.
- **(제 판단)** 부엉이의 말은 화면 말풍선으로 보여준다. 기기에 한국어 TTS가 있으면 짧게 읽어 준다. 없으면 소리 없이 넘어간다.

## 10. 확인 기준

- 기존 세이브와 백업 코드로 들어가도 영어 코인, 스테이지, 펫, 아바타가 그대로다.
- 시작할 때 영어/수학을 고를 수 있고, 지도에서 섬을 바꿀 수 있다.
- 수학 문제의 정답이 항상 맞다(생성기 테스트로 수천 개를 검사).
- 오답 보기가 정답과 값이 같지 않고, 보기끼리 겹치지 않는다.
- 분수가 문제, 보기, 힌트에서 모두 위아래로 표기된다.
- 틀리면 힌트를 볼지 고를 수 있고, 힌트에서 묶음은 한 번만 끌면 된다(마우스와 터치 모두).
- 💎는 수학 스테이지와 보스에서만 쌓이고, 수학 상점에서만 쓰인다. 🪙도 마찬가지로 영어 쪽에서만 쌓이고 쓰인다.
- 375px 폭에서 작업대 두 개, 보기, 문제가 잘리지 않는다.

## 11. 만드는 순서

1. 숫자 모듈: 분수·소수 계산, 문제 생성기, 오답 생성기, 힌트 값 계산 (+ node 테스트)
2. 분수 그리기 함수와 수학 문제 화면 (기존 `#game`을 재사용하거나 따로 만든다)
3. 저장 데이터 `S.math`, `ensureMath`, 시작 화면 섬 고르기, 수학 지도
4. 틀렸을 때 고르기 화면과 힌트 작업대 (만들기 작전 → 나머지 세 종류)
5. 보스전 연결
6. 상점 탭, `cur` 필드, 수학 아이템, 계산 할인

## 12. 만드는 사람에게 맡기는 것

- 파일 나누기. 예: `math.js`(숫자와 생성기), `math-hint.js`(작업대), `math-data.js`(스테이지 정의)
- 수학 문제 화면을 `#game`과 함께 쓸지 따로 만들지
- 수학 아이템의 정확한 목록, 이모지, 가격 (기존 가격대 30~500 안에서)
- 블록 크기, 애니메이션, 색의 정확한 값 (시안 v8을 기준으로)
- 스테이지별 숫자 범위의 세부값 (4.6 표의 범위 안에서)
