# 아이디·비밀번호 로그인 + 여러 기기 기록 동기화 설계

- 날짜: 2026-11-13
- 대상: 워드 아일랜드 (`index.html` 저장·시작 화면, 새 파일 `account.js`, `cloud.js`, `admin/`)
- 브랜치: `feature/login` — 현재 `feature/mallang-character` 끝에서 딴다 *(내 판단: 캐릭터 작업이 아직 `main`에 없어서, 그 위에 올려야 저장 구조가 맞는다)*

## 1. 왜 만드나

지금 기록(이름, XP, 코인, 단어, 영어·수학 스테이지, 캐릭터·상점)은 그 브라우저의 `localStorage` 한 칸에만 있다. 그래서 휴대폰에서 하던 아이가 태블릿을 집으면 처음부터 다시 해야 한다.

**누구나** 휴대폰이나 태블릿에서 **자기 아이디와 비밀번호**로 들어오고, 어느 기기에서든 하던 곳부터 이어서 하게 만든다. 돈은 들지 않아야 한다.

## 2. 목표 / 비목표 / 반(反)목표

**목표**
- 누구나 스스로 가입한다: 아이디 + 비밀번호 + 부를 이름. 이메일이나 전화번호는 받지 않는다.
- **로그인해야만** 게임을 할 수 있다. 지금의 "이름 쓰고 모험 시작" 화면은 로그인/가입 화면으로 바뀐다.
- 기록 `S` 전체가 계정에 저장되고, 다른 기기에서 로그인하면 그대로 불러온다.
- 한 번 로그인한 기기는 다음에 열 때 자동으로 로그인된 상태다. 설정에 **로그아웃** 버튼이 있다.
- 비밀번호를 잊으면 **관리자**가 새 비밀번호로 바꿔 준다.
- 기기에 이미 있던 기록은 그 기기에서 처음 로그인할 때 계정으로 **한 번 옮겨 온다**.
- 게임 주소는 GitHub Pages로 무료로 연다.

**비목표 (이번에 하지 않음)**
- 비밀번호 찾기(이메일·문자), 소셜 로그인(구글·카카오)
- 순위표나 다른 친구 기록 보기 등, 다른 사람의 데이터를 보는 기능
- 관리자용 웹 화면 (처음에는 관리자 컴퓨터에서 돌리는 스크립트로 충분하다)
- 두 기기에서 **동시에** 플레이할 때 기록을 합치는 것 (나중에 저장된 쪽이 이긴다)
- 아이디 바꾸기, 회원 탈퇴 화면 (필요하면 관리자가 Firebase 콘솔에서 지운다)

**반목표 (이렇게 되면 돌아가도 실패)**
- 로그인 때문에 기존 기록이 사라지는 것 — 옮겨 오기 도중 실패해도 원래 기록은 남아 있어야 한다.
- 다른 사람이 내 기록을 읽거나 바꿀 수 있는 것
- 인터넷이 잠깐 끊겼다고 게임이 멈추거나 그동안 푼 기록이 날아가는 것
- 아이에게 영어 오류 메시지(`auth/invalid-credential` 같은)가 그대로 보이는 것
- 돈이 나가는 요금제가 필요해지는 것

## 3. 제약

- 빌드 도구 없는 순수 HTML/JS 정적 페이지다. 기존처럼 `<script src>`로 붙인다.
- 지금 저장은 `localStorage['wordisland_save_v1']`의 `S` 객체 하나, `save()` / `loadSave()` / `freshSave(name)` (`index.html` 약 374~385행). 백업 코드(`encodeSave`/`decodeSave`)와 처음부터 다시하기(`resetBtn`)가 있다.
- 시작은 `renderHome()` → `startBtn`이 `freshSave(name)` (약 462~481행).
- 테스트는 `node --test tests/`, `tests/load.js`의 vm 방식을 따른다.
- 무료로 계속 돌아가야 한다.

## 4. 정한 것 (사용자가 정함)

- 대상: 누구나, 휴대폰·태블릿
- 가입: 스스로. 이메일 없음
- 비밀번호 분실: 관리자가 해결. 화면에는 안내 문구만, 연락처는 적지 않음
- 로그인 필수 (게스트 플레이 없음)
- 무료, 여러 기기
- 기존 기기 기록은 첫 로그인 때 옮겨 온다 *(사용자가 "응"이라고 답한 것을 이렇게 이해함)*

## 5. 만드는 방법 (내 판단 — 고칠 수 있음)

### 5.1 서비스
- **Firebase 무료(Spark) 요금제**: Authentication(이메일/비밀번호) + Cloud Firestore.
  - Supabase도 무료지만, 일주일 안 쓰면 프로젝트가 멈춰서 제외했다.
  - Cloud Functions는 유료(Blaze) 요금제라 쓰지 않는다.
- Firebase 프로젝트는 **사용자가 자기 구글 계정으로 직접 만든다**. 단계별 안내는 구현 때 제공한다. 웹 앱 설정값(`apiKey` 등)은 공개돼도 되는 값이라 코드에 그대로 넣는다. 보호는 보안 규칙이 한다.
- SDK는 빌드 없이 쓰려고 gstatic CDN의 **compat** 버전을 `<script>`로 붙인다 (버전 고정).

### 5.2 아이디 → 가짜 이메일
- 아이디 규칙: 영문 소문자·숫자 4~12자 (대문자로 쳐도 소문자로 바꾼다).
- Firebase에는 `<아이디>@wordisland.local`로 가입시킨다. 화면에는 아이디만 보인다.
- 아이디 중복 검사는 Firebase가 이메일 중복으로 대신 해 준다.
- 비밀번호: 6자 이상 (Firebase 최소 길이). 숫자만 써도 된다.
- 부를 이름: 기존처럼 최대 10자, `S.name`에 들어간다.
- Firebase 콘솔에서 이메일 열거 보호는 켠 그대로 둔다. "아이디가 없어요"와 "비밀번호가 틀려요"를 구분하지 않고 **"아이디나 비밀번호가 맞지 않아요"** 하나로 보여준다.

### 5.3 데이터
- Firestore 문서 `saves/{uid}` = `{ data: <S 전체>, updatedAt: <서버 시간>, id: <아이디> }`.
- 보안 규칙: 로그인한 사람은 **자기 `uid` 문서만** 읽고 쓴다. 문서 크기 제한(1MB)은 `S`에 넉넉하다.
- 기기 안 캐시: `localStorage['wordisland_save_v1:<uid>']`. 기존 키와 따로 둔다.

### 5.4 저장 흐름
- `save()`는 지금처럼 즉시 localStorage(사용자별 키)에 쓴다. 기기 사본에는 `savedAt`(기기 시각)과 `dirty`(아직 클라우드에 안 올라감) 표시를 함께 둔다.
- **클라우드에는 자주 쓰지 않는다** (무료 한도: 하루 쓰기 약 2만 번, 누구나 가입하므로 아껴야 한다). 올리는 때는:
  - 라운드·스테이지·보스 결과 화면, 상점 구매, 설정 변경 직후
  - `pagehide`/`visibilitychange`(화면을 떠날 때)
  - 그 밖에는 `dirty`일 때 **최대 30초에 한 번**
  - 한 번 올라가면 `dirty`를 끈다. 클라우드 문서에도 같은 `savedAt`을 넣는다.
- Firestore 오프라인 저장(persistence)을 켜서, 인터넷이 끊겨도 게임은 계속되고 다시 연결되면 올라간다.
- **게임을 열 때 어느 쪽을 쓰나** *(내 판단)*: 기기 사본이 `dirty`이고 `savedAt`이 클라우드보다 새로우면 **기기 사본**을 쓰고 바로 올린다. 아니면 **클라우드**를 쓴다. 이 판단은 `account.js`의 순수 함수로 두고 테스트한다.
- 클라우드 문서가 없으면 아래 5.5를 따른다.
- 두 기기 **동시** 플레이 충돌은 다루지 않는다 (나중에 올린 쪽이 이김).

### 5.5 기존 기록 옮겨 오기
- 기기에 옛 키 `wordisland_save_v1`이 있고 아직 옮긴 적이 없을 때 로그인하면:
  - 계정 기록이 **비어 있으면**(새 가입 포함): "이 기기에 있던 ○○의 기록을 이 계정으로 가져올까요?" → 예면 그 기록을 올린다(이름은 기록의 이름 유지).
  - 계정 기록이 **이미 있으면**: 두 기록의 요약(이름, 레벨, 코인)을 보여주고 어느 쪽을 쓸지 고르게 한다.
- 옮기기로 했으면 업로드가 **성공한 뒤에만** 옛 키를 `wordisland_save_v1:migrated`로 이름을 바꿔 남긴다 (지우지 않음).
- "아니요"를 고르거나 계정 기록을 고른 경우에도 옛 키를 똑같이 `:migrated`로 바꿔 남긴다 *(내 판단)*. 그래서 **한 기기에서 한 번만** 묻고, 같은 태블릿을 쓰는 형제의 계정에는 다시 묻지 않는다. 남긴 기록은 백업 코드처럼 되살릴 수 있게 지우지 않는다.

### 5.6 화면
- 시작 화면: 지금 디자인(섬, 몬스터 3마리)을 유지하고, 입력칸을 **아이디 / 비밀번호** 두 칸 + `들어가기` 버튼 + `처음이에요 (가입하기)` 링크로 바꾼다.
- 가입 화면: 아이디 / 비밀번호 / 비밀번호 확인 / 부를 이름 + `가입하기`. 아래에 "비밀번호를 잊으면 관리자에게 말해 주세요" 안내 문구만 둔다. 화면에 연락처는 적지 않는다 *(사용자가 정함)*. 로그인 화면에도 같은 문구를 작게 둔다.
- 로딩 중에는 버튼을 막고 "들어가는 중…"을 보여준다.
- 오류는 모두 쉬운 한국어로 바꿔 보여준다 (아이디 형식, 이미 있는 아이디, 비밀번호 짧음, 틀림, 인터넷 없음, 너무 많이 시도함).
- 설정 창: `로그아웃` 버튼 추가, 지금 로그인한 아이디 표시. `처음부터 다시`는 클라우드 기록도 새 기록으로 덮는다. 백업 코드 기능은 그대로 둔다.

### 5.7 관리자 비밀번호 바꾸기
- `admin/reset-password.js` (Node, `firebase-admin`): `node admin/reset-password.js <아이디> <새비밀번호>`.
- 관리자가 Firebase 콘솔에서 받은 서비스 계정 키 JSON을 `admin/service-account.json`에 둔다. 이 파일은 `.gitignore`에 넣어 **절대 커밋하지 않는다** (저장소가 공개라서).
- `admin/README.md`에 준비 방법과 사용법을 한국어로 적는다.

### 5.8 배포
- GitHub Pages로 저장소 루트를 배포한다 (`https://chemistry3333333a.github.io/eng/`).
- Firebase Authentication의 승인된 도메인에 `chemistry3333333a.github.io`를 추가한다. 로컬 개발용 `localhost`는 기본 포함.
- `tts-test.html`, `tests/` 같은 개발 파일도 함께 공개되지만 문제는 없다.

### 5.9 코드 구조
- `account.js` (순수 로직, 테스트 대상): 아이디 검증·정규화, 아이디→이메일, Firebase 오류 코드→한국어 메시지, 옮겨 오기 판단(옛 기록/계정 기록 유무에 따른 동작).
- `cloud.js`: Firebase 초기화, 로그인/가입/로그아웃, 문서 읽기/디바운스 쓰기. 외부에 작은 API만 노출.
- `index.html`: `loadSave`/`save`/`renderHome`/`startBtn`/`resetBtn`을 이 API에 맞게 바꾼다.

## 6. 빌더에게 맡기는 것

- 디바운스 시간 (2~5초 사이)
- 로그인/가입 화면의 세부 배치와 문구 (기존 시작 화면 스타일 유지)
- Firebase SDK 정확한 버전 (2주 이상 된 고정 버전)
- `cloud.js`는 실제 Firebase가 필요해서 단위 테스트 대신 로컬 실행으로 확인한다.
