# 코인상점 + 캐릭터 꾸미기 설계

- 날짜: 2026-10-19
- 대상: 워드 아일랜드 (`index.html`, `boss.js`, `words.js`)

## 1. 왜 만드나

아이들은 스테이지, 앵무새탐정, 보스전에서 코인(🪙)을 모으지만 지금은 코인을 쓸 곳이 없다. 코인으로 **나만의 캐릭터를 꾸미게** 해서 계속 공부할 동기를 만든다.

캐릭터는 이 게임 하나에만 쓰고 끝나면 안 된다. 앞으로 만들 다른 게임(예: **단어 디펜스**)에서도 같은 캐릭터가 "내 영웅"으로 활약해야 한다. 그래서 캐릭터는 특정 게임에 묶이지 않는 독립 모듈로 만든다.

## 2. 목표 / 비목표 / 반(反)목표

**목표**
- 코인으로 꾸미기 아이템을 사고, 입히고, 벗길 수 있다.
- 꾸민 캐릭터가 지도와 게임 화면에 보인다.
- 캐릭터와 아이템은 다른 게임이 그대로 불러 쓸 수 있는 구조다.
- 상점 자체도 영어 공부가 된다. 아이템 이름이 영어 단어이고, 누르면 발음이 나온다.

**비목표 (이번에 하지 않음)**
- 단어 디펜스 게임 구현 (별도 프로젝트, §9는 연결 방향만 적음)
- SVG나 그림 파일로 만든 캐릭터 (1단계는 이모지)
- 서버, 계정, 친구끼리 보여 주기

**반목표 (이렇게 되면 기술적으로 돌아가도 실패)**
- 아이템이 정답을 알려 주거나 문제를 건너뛰게 해서 **공부를 덜 하게 만드는 것**
- 랜덤 뽑기(가챠)처럼 확률로 무엇이 나올지 모르는 구매. 어린이 대상이므로 넣지 않는다.
- 기존 세이브가 깨지거나 백업 코드 복구가 실패하는 것

## 3. 제약

- 빌드 도구 없는 순수 HTML/JS 정적 페이지다. `<script src>`로 파일을 붙이는 기존 방식을 따른다.
- 저장은 `localStorage`의 `wordisland_save_v1` 하나(`S` 객체)이고, 백업 코드는 `S` 전체를 base64로 만든 것이다.
- 기존 화면 전환 방식(`section.screen` + `show(id)`), 공용 함수(`$`, `toast`, `speak`, `sfxGood` 등)를 그대로 쓴다.
- 기기 내장 TTS(`speak`)와 `audio/*.mp3`가 이미 있다.
- 보스전 펫 데이터(`S.pets`, `S.petOn`, `boss.js`의 `INFO[id].pet`)가 이미 있다.

## 4. 구조

새 파일 두 개를 추가한다. 로드 순서는 `words.js` → `items.js` → `avatar.js` → 본 게임 스크립트 → `boss.js`이다.

### 4.1 `items.js` — 아이템 목록 (데이터만)

```js
const ITEMS = [
  {id:'hat_cap',   slot:'hat',  word:'cap',   icon:'🧢', price:30,  perk:null,     unlock:null},
  {id:'hand_wand', slot:'hand', word:'wand',  icon:'🪄', price:120, perk:'splash', unlock:{level:5}},
  {id:'hat_crown', slot:'hat',  word:'crown', icon:'👑', price:400, perk:null,     unlock:{trophies:5}},
  ...
];
```

- `word`: 아이템의 영어 이름. 상점에서 발음을 들려줄 때 쓴다.
- `unlock`: `{level:n}`, `{trophies:n}`, `{dex:n}`(도감 단어 수) 중 하나이거나 `null`이다.
  - **(제 판단)** `trophies`는 **별 1개 이상으로 깬 보스 수**다. `Object.values(S.trophies).filter(v => v > 0).length`로 세며, 보스는 모두 9마리다. 잠금 문구 예: "보스 5마리 물리치기"
- `perk`: 다른 게임이 해석할 특성 태그(§6)이거나 `null`이다.

### 4.2 `avatar.js` — 캐릭터 모듈 (`window.Avatar`)

어떤 게임이든 아래 함수만 쓰면 된다. 내부에서 무엇으로 그리는지(이모지인지 SVG인지)는 바깥에 숨긴다.

```js
Avatar.render(el, {size:'s'|'m'|'l', pose:'idle'|'attack'|'cheer'|'hurt'})  // el 안에 캐릭터를 그림
Avatar.equipped()        // {hat:'hat_cap', hand:null, ...}
Avatar.perks()           // 장착 아이템의 perk 목록, 예: ['splash']
Avatar.owns(id) / Avatar.buy(id) / Avatar.equip(id) / Avatar.unequip(slot)
Avatar.canBuy(id)        // {ok:true} 또는 {ok:false, reason:'coins'|'locked'|'owned'}
```

`buy`는 코인 차감, 소유 추가, `save()` 호출까지 한 번에 처리한다. 화면 갱신은 부르는 쪽이 한다.

### 4.3 저장 데이터

```js
S.avatar = { body:'kid1', equip:{hat:null, face:null, hand:null, back:null, effect:null} }
S.owned  = []                         // 산 아이템 id 목록
S.shop   = { freeGiven:false, dealDay:'', dealId:'' }
```

- **이전(마이그레이션)**: 세이브를 불러올 때와 백업 코드로 복구할 때 모두 `ensureAvatar(S)`를 불러서 빠진 필드를 기본값으로 채운다. 기존 데이터는 절대 지우지 않는다. `S.v`는 1로 둔다.
- 백업 코드는 `S` 전체를 담으므로 별도 처리 없이 캐릭터도 함께 옮겨진다.

## 5. 캐릭터 모습과 슬롯

### 5.1 기본 몸
**(제 판단)** 6종(🧒 👧 👦 🐱 🐶 🐰)이고, 무료이며 언제든 바꿀 수 있다. 따로 온보딩 화면은 만들지 않는다. 기본값은 `kid1`(🧒)이다. **상점에 처음 들어오면** 먼저 몸 고르기 창을 띄우고, 이어서 첫 방문 선물(§7.4)을 준다. 그 뒤로는 상점의 🧍몸 탭에서 바꾼다. 홈 화면과 이어하기 흐름은 바꾸지 않는다.

### 5.2 슬롯

| 슬롯 | 예시 단어 | 그리는 위치 |
|---|---|---|
| `hat` 머리 | cap, crown, helmet, bow | 몸 위쪽에 겹침 |
| `face` 얼굴 | glasses, mask | 얼굴 위에 겹침 |
| `hand` 손 | wand, sword, bow(활은 `bow_arrow`), balloon | 몸 오른쪽 아래 |
| `back` 등 | cape, wings | 몸 뒤쪽(z-index 아래) |
| `effect` 효과 | sparkle, fire, heart, star | 캐릭터 주변에 떠다니고, 정답을 맞히면 터짐 |
| 펫 | 보스전에서 구한 친구 | 캐릭터 옆. 기존 `S.petOn`을 그대로 쓴다 (상점에서 팔지 않음) |

**(제 판단)** 펫은 `Avatar.render(el, {..., pet:true})`로 모듈이 함께 그린다. 그러려면 펫 이모지와 이름을 `boss.js`의 `INFO`에서 `items.js`의 `PETS = {bossId: ['🐣','삐약이'], ...}`로 옮기고, `boss.js`는 `PETS`를 참조한다. 이렇게 하면 다른 게임이 펫 코드를 반복하지 않아도 된다.

**(제 판단)** 1단계 아이템은 슬롯마다 4~6개, 모두 약 24개로 시작한다. 정확한 목록과 이모지는 만드는 사람이 정한다. 단 조건이 있다. 이름이 아이들이 배울 만한 쉬운 영어 단어여야 하고, 같은 슬롯 안에서 가격대가 골고루 퍼져 있어야 한다.

### 5.3 그리는 방식
- 1단계는 **이모지 레이어 겹치기**다. `position:absolute`로 슬롯마다 위치와 크기를 지정한다.
- 이모지는 기기(안드로이드, iOS, 윈도우)마다 모양과 위치가 조금씩 다르다. 슬롯별 위치값을 `avatar.js` 한 곳에 모아 두고 고치기 쉽게 한다.
- 자세(`pose`)는 CSS 애니메이션으로 표현한다. idle=둥실, attack=앞으로 툭, cheer=점프, hurt=흔들림.

## 6. 특성(perk) 규칙

- 아이템마다 특성 태그를 하나 붙일 수 있다. 1단계 태그는 `splash`(범위), `slow`(감속), `shield`(보호), `pierce`(관통), `coin`(코인 보너스)이다.
- **각 게임은 자기가 아는 태그만 해석하고 나머지는 무시한다.** 태그의 뜻은 게임마다 달라도 된다.
- 금지: 정답 표시, 보기 줄이기, 문제 건너뛰기, 시간 멈춤처럼 학습을 대신해 주는 효과.
- **(제 판단)** 1단계의 기존 게임(스테이지, 앵무새, 보스전)에서는 특성이 **게임 효과를 내지 않는다.** 꾸미기는 순수하게 외형이고, `effect` 슬롯의 정답 이펙트만 보인다. 특성은 단어 디펜스에서 처음 의미를 갖는다. 이렇게 하면 기존 게임의 난이도와 코인 밸런스가 그대로 유지된다.

## 7. 상점

### 7.1 진입
- 지도 하단(`mapfoot`)에 `🛍️ 상점` 버튼을 추가한다.
- 지도 상단 `whoTxt` 왼쪽에 작은 캐릭터(`size:'s'`)를 보여 주고, 누르면 상점의 "내 캐릭터" 탭으로 간다.

### 7.2 화면 (`section#shop`)
```
[⬅️]   🛍️ 상점                 🪙 235
┌──────────────────────────────┐
│     (큰 캐릭터 미리보기 l)     │
└──────────────────────────────┘
[🔥오늘의 특가] [🎩][👓][🗡️][🎒][✨][🧍몸]
┌────┐┌────┐┌────┐
│🧢   ││👑🔒 ││🪄   │   ← 아이템 격자
│cap  ││crown││wand │
│🪙30 ││🏆5  ││착용중│
└────┘└────┘└────┘
```
- 아이템 칸을 한 번 누르면 **피팅**이 된다. 미리보기 캐릭터에 입혀 보고 `speak(word)`로 발음을 들려준다. 아직 사지 않았으면 아래에 `🪙 30 사기` 버튼이 나온다.
- 이미 산 아이템은 `입기`/`벗기` 버튼이 나온다.
- 잠긴 아이템은 조건을 보여 준다. 예: "🏆 트로피 5개 필요", "레벨 5 필요"
- 상점을 나가면 피팅 중이던(사지 않은) 아이템은 원래대로 돌아간다.
- 코인이 모자라면 버튼을 흐리게 하고 "코인이 N개 더 필요해요"를 보여 준다.

### 7.3 영어로 주문하기 (선택 할인)
- `사기`를 누르면 "영어로 주문하면 10% 할인!" 선택지가 나온다. 아이템 단어 소리를 듣고 그림 3개 중 맞는 것을 고른다.
- 맞히면 10% 할인을 해 주고, 틀려도 정가로 살 수 있다(벌칙 없음). 건너뛰기도 가능하다.
- **(제 판단)** 할인은 겹치지 않는다. 오늘의 특가 아이템에는 "영어로 주문하기"를 띄우지 않고 30% 할인만 적용한다. 최종 가격은 `Math.ceil(price * (1 - 할인율))`이다.
- 오답 보기 그림은 같은 슬롯의 다른 아이템 아이콘에서 고른다.

### 7.4 첫 방문 선물
- 상점에 처음 들어오면(`S.shop.freeGiven === false`) 30코인 이하 아이템 중 하나를 골라 무료로 받는다. 받으면 바로 입혀 준다.

### 7.5 오늘의 특가
- 하루에 1개, 잠기지 않았고 아직 사지 않은 아이템 중 하나를 30% 할인한다.
- 날짜는 기존 `today()` 문자열을 쓰고 `S.shop.dealDay`, `S.shop.dealId`에 저장한다. 날짜가 바뀌면 새로 고른다. 살 수 있는 아이템이 없으면 특가 탭을 숨긴다.

### 7.6 게임 화면 속 캐릭터 (사용자 결정)

스테이지, 보스전, 앵무새탐정 화면에 **꾸민 캐릭터 전체**가 나온다.

- **(제 판단)** 위치는 지금 보스전 펫(`#petPal`)이 있는 **왼쪽 아래 구석**이다. 캐릭터는 `size:'s'`이고 펫은 그 오른쪽에 붙는다. 기존 `#petPal`은 `Avatar.render(el,{size:'s', pet:true})` 하나로 바꾼다. 펫 응원 말풍선(`petCheer`)은 유지한다.
- 스테이지와 보스전은 같은 `section#game`을 쓰므로 한 곳에만 배치하면 된다. 앵무새탐정(`section#parrot`)에도 같은 방식으로 하나를 둔다. 결과 화면(`result`, `pResult`)에는 `cheer` 자세의 `size:'m'` 캐릭터를 둔다.
- 반응: 정답이면 `cheer`와 `effect` 이펙트, 오답이면 `hurt`. 보스 반격으로 하트를 잃을 때도 `hurt`다.
- 캐릭터는 `pointer-events:none`이어서 몬스터나 보기 터치를 막지 않는다. 375px 폭에서 보기 버튼과 겹치면 크기를 줄이거나 반투명하게 하고, 판단은 만드는 사람이 한다.

## 8. 코인 경제

현재 수입(대략): 스테이지 10~25, 앵무새 10~20, 보스 40~90.

**(제 판단)** 가격대:
- 기본 30~60 (스테이지 2~3판)
- 중급 100~200
- 레어 300~500 (레벨, 트로피, 도감 조건으로 잠김)

1단계 아이템 전체를 사는 데 대략 4,000~5,000코인이 들도록 맞춘다. 정확한 가격은 만드는 사람이 이 범위 안에서 정한다.

## 9. 다른 게임과의 연결 (단어 디펜스, 미래)

이번 작업에서는 만들지 않는다. 다만 아래 장면이 가능하도록 `Avatar` API를 설계한다.

- 섬의 성 앞에 내 캐릭터(`Avatar.render(el,{size:'m'})`)가 서 있고, 단어 몬스터들이 걸어온다.
- 단어 소리를 듣고 맞는 몬스터를 누르면 캐릭터가 `pose:'attack'`을 하고, `hand` 아이템 아이콘이 투사체로 날아간다(지팡이는 마법탄, 활은 화살).
- `Avatar.perks()`에 `splash`가 있으면 범위 공격, `slow`가 있으면 감속 같은 식으로 해석한다.
- 펫은 보조 공격을 한다.

## 10. 만드는 순서

1. `items.js`, `avatar.js`, `ensureAvatar` 마이그레이션 (로드와 복구 둘 다)
2. 상점 화면: 탭, 격자, 피팅, 사기/입기/벗기, 잠금 표시
3. 첫 방문 선물, 오늘의 특가, 영어로 주문하기
4. 지도 상단 캐릭터, 게임·보스전·앵무새탐정·결과 화면 캐릭터와 반응 (§7.6), 펫 표시를 `Avatar`로 옮기기

## 11. 확인 기준

- 기존 세이브로 들어가도 오류가 없고 코인, 스테이지, 펫이 그대로다.
- 기존 백업 코드(캐릭터 필드 없음)로 복구해도 정상 동작한다.
- 사기, 입기, 벗기 후 새로고침해도 유지된다.
- 코인이 부족하거나 잠겨 있으면 살 수 없고, 코인이 음수가 되지 않는다.
- 모바일 폭(375px)에서 상점 격자와 미리보기가 잘리지 않는다.
- 스테이지, 보스전, 앵무새탐정에서 캐릭터가 보이고, 보기나 몬스터 터치를 가리지 않는다. 보스전 펫과 응원 말풍선이 전처럼 동작한다.

## 12. 만드는 사람에게 맡기는 것

- 아이템 정확한 목록, 이모지, 가격 (§5.2, §8의 조건 안에서)
- 슬롯별 위치와 크기값, 애니메이션 세부
- 상점 색상과 버튼 스타일 (기존 `.btn`, `.pill`, `.panel` 스타일을 따름)
- CSS를 `avatar.js` 안에 넣을지 `index.html`에 넣을지 (`boss.js`처럼 JS에서 스타일을 주입하는 방식도 가능)
